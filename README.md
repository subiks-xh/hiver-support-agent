## What This Is

An AI-powered customer support agent built for **Amazon (@AmazonHelp Twitter)**.

Given a customer message, the agent:

1. **Classifies** it into one of 7 intents
2. **Drafts a reply** grounded in real historical Amazon conversations
3. **Decides** whether to auto-handle or escalate to a human

**The proof is worth more than the system** — see evaluation results below.

## What Is Misleading About 67.7%?

_(Full analysis in REPORT.pdf — summary here)_

1. **Label contamination** — ground truth labels generated by same
   model family as agent. Only 52/189 manually verified.

2. **Class imbalance** — CUSTOMER_COMPLAINT is 28.6% of data.
   Trivial baseline gets 28.6% for free.

3. **Batch classification** — 10 messages per API call means model
   sees neighbouring messages. Invalid in real production.

4. **Distribution mismatch** — 2019 Twitter data vs real 2026 messages.

5. **LLM judge not independent** — same model family judging own outputs.

## 7 Intents Defined

| Intent             | Description                                    |
| ------------------ | ---------------------------------------------- |
| ORDER_STATUS       | Tracking, delivery status, shipping updates    |
| DELIVERY_ISSUE     | Wrong address, not delivered, lost package     |
| RETURN_REFUND      | Returns, refunds, money back requests          |
| PAYMENT_ISSUE      | Charges, billing errors, unauthorized payments |
| TECHNICAL_ISSUE    | App, device, website problems                  |
| PRODUCT_ISSUE      | Defective, wrong, or missing items             |
| CUSTOMER_COMPLAINT | Dissatisfaction, legal threats, escalations    |

## System Architecture

```
Customer Message
      │
      ▼
┌─────────────────────┐
│  Intent Classifier  │  ← LLM prompt (openai/gpt-oss-20b)
└────────┬────────────┘
         │ intent + confidence
         ▼
┌─────────────────────┐
│   Retrieval (RAG)   │  ← Keyword search over 4,697 conversations
└────────┬────────────┘
         │ top-3 similar examples
         ▼
┌─────────────────────┐
│    Reply Drafter    │  ← LLM grounded in retrieved examples
└────────┬────────────┘
         │ draft reply
         ▼
┌─────────────────────┐
│ Escalation Decider  │  ← Hard rules + LLM hybrid
└────────┬────────────┘
         │
    AUTO_HANDLE or ESCALATE
```

---

## Escalation Rules

Auto-escalate if ANY of these:

- Keywords: `lawyer`, `sue`, `court`, `fraud`, `hack`, `police`
- Intent is `PAYMENT_ISSUE` (always needs human verification)
- Classification confidence < 0.4 (unclear intent)
- LLM judges message as emotionally charged or complex

---

## Top 5 Failure Modes

1. **ORDER_STATUS ↔ DELIVERY_ISSUE** (9 cases) — "delayed" triggers wrong intent
2. **COMPLAINT ↔ TECHNICAL** (8 cases) — frustration + tech words confuses model
3. **Short messages** (17 cases, 27.9%) — under 80 chars = not enough context
4. **Non-English** (observed) — ASCII filter not perfect
5. **Sarcasm** (observed) — "packed efficiently" read literally when sarcastic

## Key Design Decisions

See full Decision Log in `REPORT.pdf`. Top decisions:

- **Chose Amazon** — largest dataset, most diverse intents
- **Groq not OpenAI** — free tier, sufficient quality
- **7 intents** — tested 10, accuracy dropped. 7 covers 95% of cases
- **Keyword RAG** — faster, zero cost, interpretable
- **Batch classification** — solves rate limit on free tier
- **PAYMENT_ISSUE always escalated** — financial safety
